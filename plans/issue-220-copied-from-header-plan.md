## Implementation

### Extractor: `--scan-header`

A new constant `HEADER_PHRASES` (lowercase):

```js
const HEADER_PHRASES = [
  'copied from',
  'fork of',
  'based on',
  'duplicate of',
  'ported from',
];
const HEADER_SCAN_LINES = 30;
```

A new helper `scanHeader(buf)`:

1. Decode bytes as UTF-8, split into lines on `\n` (after `\r\n` → `\n` normalization).
2. Take the first `HEADER_SCAN_LINES` (or all if shorter).
3. For each line: lowercase, search for the first phrase present (sequential by line, then by phrase order — earliest-line wins; phrase precedence is the tie-breaker within a line).
4. `text` is the raw line trimmed of trailing newline / `\r` / trailing whitespace — single-line by construction (we split on `\n` first). No multi-line concerns.
5. On a hit: return `{ line: 1-indexed, phrase, text }`.
6. On no hit: return `null`.

The reader is line-by-line and lowercases each line independently (no whole-file lowercasing); `text` is the raw line trimmed of trailing newline/whitespace, preserving original casing for display in the report.

**Field-presence strategy**: when `--scan-header` is set, **every** record carries `header_match` (set to `null` when no match). When `--scan-header` is unset, the field is **omitted entirely**. This mirrors how `generated: false` is always present once the extractor emits it. The query consumer always runs with `--scan-header` set (the binary's manifest gate guarantees this), so the query can rely on `header_match` being present-or-null and filter with `select(.header_match != null)`.

### Why a deny-list is *not* in v1

Issue body §"Precision expectation" notes that license-attribution headers (e.g., "based on the MIT-licensed implementation by X") could false-positive. The deny-list is **deferred** because:

1. The fixture includes a "based on the MIT-licensed" row to track whether v1 surfaces it. The triage path is "look at the cluster, dismiss license-attribution rows by eye" — same workflow as `versioned-type-pairs` documents for its `IPv4/IPv6` false-positive class.
2. A deny-list adds calibration burden (which phrases? case-sensitive?) without removing the manual review step — the audit-window report is already read by a human or LLM judge.
3. If real-world calibration shows >5% false-positive rate on a single project, file a follow-up to add an `EXCLUDE_PHRASES` env var (mirrors the `INCLUDE_GENERATED` pattern in `versioned-type-pairs`).

Documented in the query header as a known v1 limitation.

### Query

Front-matter:

```jq
#! query: copied-from-header
#! shape: cluster
#! catalog: file-hashes
#! formats: text, jsonl
#! desc: Files whose top comment self-confesses as a fork ("copied from", "fork of", etc.).
```

The query operates on file-hashes entries, filtering on `header_match != null`. Each file produces one single-member cluster row (the finding *is* the per-file match — there is no grouping). The single-member envelope matches `orphan-infer-model`'s convention.

Cluster_id format: `copied-from-header:<package>:<file>`. One cluster_id per matched file; uniqueness guaranteed by the (package, file) pair, which is unique within `file-hashes.json` per the file-hashes extractor's contract.

Member shape:

```jsonc
{
  "package": "...",
  "file": "...",
  "line": 1,                  // 1-indexed source line of the match
  "phrase": "copied from",
  "text": "// Copied from DebugPanel for shader performance testing."
}
```

Sort order: `(package, file)` ascending. Stable across gojq and stedolan/jq.

### Text-mode render

Each row renders one block:

```
[copied from] cid=copied-from-header:main:Shared/Wallpaper/Examples/.../DebugHUD.swift
   main:Shared/.../DebugHUD.swift:1
     // Copied from DebugPanel for shader performance testing.
```

The leading `[<phrase>]` annotation makes the phrase searchable in scrollback. The member detail follows the canonical-renderer convention (asterisk-vs-space marker not used here since file-hashes rows don't carry `touched_in_window`).
