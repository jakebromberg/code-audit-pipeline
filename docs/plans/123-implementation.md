# Implementation plan — #123 PR-comment Action

Issue: [#123 Dev-flow integration: GitHub Action — "clusters affected by this PR" comment](https://github.com/jakebromberg/code-audit-pipeline/issues/123). Parent: [#120 Dev-flow integrations](https://github.com/jakebromberg/code-audit-pipeline/issues/120). Sibling consumer of `audit-core` composite alongside the merged [#154 publication path](https://github.com/jakebromberg/code-audit-pipeline/issues/154).

The Action posts a sticky "structural impact" comment on every PR. The comment lists cluster matches (exact-duplicates, name-collisions, cross-package-shadows, near-duplicates, etc.) whose members include files touched by the PR. The comment is edited in place across force-pushes via a marker header (sticky-comment).

## What's already on `main` we can reuse

- **`audit-core` composite** (`.github/actions/audit-core/action.yml`, shipped in #154/PR1). Detects language(s), installs toolchain + `code-audit` binary, runs every applicable extractor, emits `.audit/catalogs/` as an output. Already supports the `binary-version`, `include-tests`, `audit-root`, `github-token` inputs we need.
- **`code-audit report` subcommand** (`internal/cli/report.go`). Already iterates every runnable query in `pipeline/queries/`, runs each in JSONL mode, dispatches every row through `internal/render/{cluster,pair,metric}.go`, and assembles a markdown document. **This is the renderer backbone for #123** — see "Renderer choice" below for the divergence from the issue body.
- **`code-audit extract typescript --list-relevant`** (shipped in #159/PR244). Reads NUL- or newline-separated paths on stdin, normalizes (CRLF / Windows backslash / `./` prefix / whitespace), applies the extractor's own walk predicate (SKIP_DIRS + EXT_RE + TEST_DIRS/TEST_FILE_RE), and emits the kept subset. This is the canonical exposure of the TypeScript walker — touched-file resolution in this Action reuses it.
- **`touched_in_window` flag** in catalog rows. Cluster queries already emit it per-member and prefix touched members with `*` in text mode. The PR-comment filter is "cluster contains any member with `touched_in_window == true` OR cluster contains any member whose `file` appears in `touched.json`" — the second clause is what the new `--touched` filter at the `report` level adds.
- **`pipeline/queries/touched-window-debt-summary.jq`** — meta-query that already groups clusters by type and counts touched intersections. PR comments will surface a one-liner from this query as the comment header (e.g. "3 cluster types touched, 7 clusters affect 4 files").
- **`marocchino/sticky-pull-request-comment@v2`** — vetted MIT-licensed, ACSL-compatible. Listed in the issue's open questions as confirmed.

## Renderer choice — divergence from the issue body, justified

The issue body (#123 §"Implementation recommendations" item 2) calls for **`scripts/render-pr-comment.mjs`** — a Node.js renderer iterating the queries dir, applying the cluster-filtering rule, emitting markdown. That recommendation predates `internal/cli/report.go` (the Go `code-audit report` subcommand, added in a later substrate consolidation).

Building a second renderer in Node would:

1. **Duplicate shape-rendering logic.** `internal/render/cluster.go`, `metric.go`, `pair.go` already know how to render every query shape. A Node parallel would diverge — exactly the SKIP_DIRS / EXT_RE drift footgun #244 spent commits unifying.
2. **Diverge on query discovery semantics.** The Go report driver already filters `_canonical.jq`, handles missing front-matter, and skips queries that don't support `jsonl`. Rebuilding this in Node would be a per-line port.
3. **Diverge on `code-audit` binary capabilities.** Project principle is "deterministic extraction, deterministic clustering, agentic synthesis sparingly." A `code-audit pr-comment` Go subcommand sits cleanly in lane 2; a Node script next to it does not.

**Decision: extend `code-audit report` rather than ship a Node renderer.** Specifically:

- Add `code-audit report --touched <path.json>`: a path to a JSON array of repo-relative file paths (the touched-file set from `gh pr view`).
- Add the cluster-filtering predicate at the report driver level — drop clusters where no member has `touched_in_window == true` AND no member's `.file` matches any entry in the touched set. Filtering happens after engine.Run, on the parsed JSONL rows, so each query's own logic is unchanged.
- Add `code-audit report --mode pr-comment`: comment-friendly output mode. Drops the "Skipped queries" footer, drops the per-section "Generated by…" header, prepends the sticky-comment marker comment (`<!-- code-audit-pipeline-v1 -->`), and caps cluster output (truncate with "+N more clusters omitted" when the rendered length crosses a threshold — implementation note below).
- Add `code-audit report --on-extraction-failure quiet|loud`: when the runner sets `--mode pr-comment`, the default is `quiet` (emit a one-line `> code-audit: report unavailable for <language>; see workflow run logs.` body and exit 0); regular `code-audit report` keeps the existing fail-loud behavior. (Wording reconciled with code in iteration-3 review.)

The composite action's renderer step becomes a single `code-audit report --root . --touched touched.json --mode pr-comment --output comment.md` invocation. No new Node script. **This is the most consequential plan choice and the one most worth pushback.**

## Design

### 1. Renderer extensions (`internal/cli/report.go`)

**New flags:**

| Flag | Default | Purpose |
|---|---|---|
| `--touched <path>` | unset | Path to a JSON file containing `[".audit-relative", "paths.ts", ...]`. When set, cluster-filtering predicate is applied. |
| `--mode <text\|pr-comment>` | `text` | Output mode. `text` is the existing `findings-YYYY-MM-DD.md` shape. `pr-comment` drops "Skipped queries" + the "Generated by…" header, prepends the sticky marker, applies the size cap. |
| `--on-extraction-failure <loud\|quiet>` | inferred from `--mode` (`loud` for text, `quiet` for pr-comment) | When `quiet`, fail-quiet errors (see "Error detection and fail-quiet boundary" below) produce a single-line body and exit code 0. When `loud`, behavior is the existing (exit non-zero) path. |
| `--size-cap-bytes <N>` | `60000` | Hard cap on rendered comment length. Past this, drop further sections and append "+N more clusters omitted (see audit run logs for full output)." Default leaves ~4KB headroom below GitHub's 65,536-character PR comment cap. |
| `--marker <string>` | `code-audit-pipeline-v1` | Sticky comment marker. Emitted as `<!-- <marker> -->` on the first line of `pr-comment` mode output. |

**Filter design.** Add a new type and function in `internal/cli/report.go`:

```go
// touchedSet is the parsed --touched payload normalized to forward-slash,
// trimmed, with ./ prefix collapsed — matches the catalog's path canonical
// form (see extractors/typescript/_lib/walk-predicate.mjs:34 normalizePath,
// ported to Go as internal/diffmatch/pathnormalize.go:Normalize).
type touchedSet map[string]struct{}

// loadTouchedSet reads --touched <path>, expects a JSON array of strings,
// normalizes each entry. Validation rules:
//   - File missing/unreadable: return error (usage error, exit 2).
//   - JSON parse failure: return error (usage error, exit 2).
//   - Top-level value is not an array: return error (usage error, exit 2).
//   - Any element is not a string: return error citing the offending index
//     (usage error, exit 2). Coercion/skip-non-string is explicitly NOT
//     done — the caller controls the input and a non-string element is a
//     bug in the resolve-touched.sh step that should fail loud.
//   - Empty array: returns an empty (non-nil) set. The renderer treats
//     this as "no files touched" — every cluster is filtered out and the
//     "no structural impact" body is emitted.
//   - Empty/absent file (--touched not passed): returns nil. The renderer
//     skips filtering entirely (passes every row through).
func loadTouchedSet(path string) (touchedSet, error) { ... }

// filterRowsByTouched drops cluster rows where no member has
// touched_in_window==true AND no member's normalized .file is in touched.
// Pair and metric shapes are passed through unchanged: pair queries are
// already two-document joins (the touched-side is what produced them); the
// touched-window-debt-summary metric self-filters via its own .members[].
// touched==nil short-circuits to pass-through.
func filterRowsByTouched(rows []render.Row, header *frontmatter.Header, touched touchedSet) []render.Row { ... }
```

**Hook point:** `runReportQuery` in `report.go:107` already parses JSONL into rows before passing them to `render.Dispatch`. We refactor so the JSONL→[]Row step is separable from the Row→markdown step; the filter runs in between. The renderer (`internal/render/`) stays pure — it never sees `touched`.

**Pseudocode for filterRowsByTouched on a cluster row:**

```go
for _, row := range rows {
    if !isCluster(header.Shape) { keep(row); continue }
    members, _ := row["members"].([]any)
    var anyTouched bool
    for _, m := range members {
        mm, _ := m.(map[string]any)
        if t, _ := mm["touched_in_window"].(bool); t { anyTouched = true; break }
        if f, _ := mm["file"].(string); f != "" {
            if _, hit := touched[normalize(f)]; hit { anyTouched = true; break }
        }
    }
    if anyTouched { keep(row) }
}
```

`normalize(f)` is a Go port of the algorithm at `extractors/typescript/_lib/walk-predicate.mjs:34` (the `normalizePath` function shipped in #244):

```javascript
// From extractors/typescript/_lib/walk-predicate.mjs (lines ~34–46, exact form):
function normalizePath(relPath) {
  if (typeof relPath !== 'string') return null;
  let p = relPath;
  if (p.endsWith('\r')) p = p.slice(0, -1);
  p = p.trim();
  if (p === '') return null;
  p = p.replace(/\\/g, '/');
  while (p.startsWith('./')) p = p.slice(2);
  return p;
}
```

The Go port lives at `internal/diffmatch/pathnormalize.go` as `func Normalize(s string) string` (returns empty string instead of `null` for non-string / empty input — Go's stronger typing makes the type guard moot). Parity test at `internal/diffmatch/pathnormalize_test.go` reuses the (input, expected-output) cases from `extractors/typescript/test/walk-predicate.test.mjs:normalizePath` (shipped in #244) — covering CRLF, `./` prefix, backslash, leading/trailing whitespace, and combined-form inputs. The cases are duplicated into the Go test rather than parsed from the `.mjs` file at test-time, because the inputs are short string literals and the parity guarantee is what we're asserting; the duplication is the point. A `// PARITY SOURCE:` comment at the top of `pathnormalize_test.go` cites the TypeScript file path + line range so a future contributor updating one side knows to update both.

**Error detection and fail-quiet boundary.** Each of these errors in the report pipeline can be triggered by an upstream failure; the table maps them to behavior under `--mode pr-comment --on-extraction-failure quiet`:

| Error source | Layer | Detection site | quiet behavior |
|---|---|---|---|
| `--touched <path>` file missing/unreadable | caller-input | `loadTouchedSet` (new) | **exit 2, usage error.** Caller-controllable — the workflow file must fix it. |
| `--touched <path>` JSON malformed or contains non-string element | caller-input | `loadTouchedSet` validation | **exit 2, usage error.** Same reasoning. |
| Catalog file (e.g. `.audit/catalogs/type-catalog.json`) missing | upstream extraction | `wireCatalogs` (`report.go:121`) returns `err`; today this falls into `sectionResult.err` | **fail-quiet:** the extractor failed before the report ran. The PR-comment surface stays current with the prior PR's body. |
| Catalog file present but malformed JSON | upstream extraction | `wireCatalogs` succeeds; `engine.Run` fails on read | **fail-quiet:** the catalog file is the extractor's output. A corrupt file means the extractor crashed mid-write (e.g. killed by the runner) or has a bug. From the comment-surface consumer's perspective, this is indistinguishable from "no catalog" — the extractor failed to produce a usable artifact. |
| `engine.Run` jq syntax error | bundled-query | `sectionResult.err != nil` | **fail-quiet:** the query is shipped with this binary. A jq syntax error means a query-author bug landed in a release. Failing the PR loudly puts the burden on consumer repos rather than the pipeline author. The runner log carries the loud body for diagnosis. |
| Renderer dispatch error (shape mismatch) | internal | `renderJSONL` returns `err` | **fail-quiet:** internal pipeline bug, same handling. |
| Front-matter parse error | bundled-query | `sectionResult.skipped` | unchanged: query is dropped, others continue. Not a fail-quiet trigger because other queries still produce real output. |
| Touched-file path normalization produces empty set | not an error | n/a | proceed; report renders to "no structural impact" body via the no-cluster path. |

The unifying rule: **caller-input errors (bad `--touched`) exit 2 loud so the consumer fixes the workflow file. Pipeline-internal errors (extractor crash, query bug, renderer bug) fail-quiet so the comment surface stays current and the consumer is not blocked.** The justification for treating "catalog missing" and "catalog corrupt" identically: both look the same from outside the binary (the extractor's output is unusable), and both have the same remediation (rerun the extractor / file a bug upstream). The runner log carries the loud body in all fail-quiet cases for diagnosis.

Implementation: `composeReport` already tracks `failed bool`; we extend it to also track `errorKind` (catalog / engine / render). In `--mode pr-comment --on-extraction-failure quiet`, `failed == true` discards the entire body and emits:

```
<!-- code-audit-pipeline-v1 -->
> code-audit: report unavailable for <comma-separated detected languages>; see workflow run logs.
```

The loud-mode body is written to stderr so the runner logs carry it.

**Sticky marker placement.** marocchino/sticky-pull-request-comment@v2 scans the comment body for `<!-- <header> -->` via substring match — it does NOT require byte-0 placement. (Source: [marocchino/sticky-pull-request-comment README §"How it works"](https://github.com/marocchino/sticky-pull-request-comment), confirmed in v2.x release notes.) We emit it on line 1 for deterministic placement and grep-ability; this also makes the `--marker` flag testable via byte-equal golden comparison.

**Size cap behavior.** The cap is per-section atomic: when the next section would push the running byte count over the cap, the whole section is dropped (no partial cluster rendering) and the truncation footer is appended. If a single section is itself larger than the cap (degenerate case — a 100KB `near-duplicates.jq` output on a giant repo), it is still dropped intact and the footer notes the section name. Sections render in deterministic query-name order (alphabetical, matching `listQueries`), so a given (catalog, touched, cap) input is byte-reproducible.

**Test strategy.** The plan adopts the existing render-package test pattern: testdata fixtures + `-update` flag for regeneration. Specifically:

- `internal/cli/testdata/pr-comment/<case>/catalog.json` — input catalog.
- `internal/cli/testdata/pr-comment/<case>/touched.json` — input touched set.
- `internal/cli/testdata/pr-comment/<case>/expected.md` — golden output.
- `internal/cli/testdata/pr-comment/<case>/args.txt` (optional) — extra flags (e.g. `--size-cap-bytes 200` for the size-cap case).

The layout differs from `internal/render/testdata/<shape>/<name>.{jsonl,md}` (which is keyed on render-shape) because pr-comment cases exercise the *composition layer* across multiple shapes in a single fixture — a single multi-shape catalog flows through filtering, mode selection, and size-cap together. Keying by case (rather than by shape) lets each case scope its own inputs (catalog + touched + args) into one directory.

The test driver is `TestReportPRComment` in `internal/cli/report_test.go`, modeled on `internal/render/render_test.go:TestRenderShapes` (uses `flag.Bool("update", ...)` for regeneration, walks subdirectories under `testdata/pr-comment/`, runs each as a sub-test, reports diffs on mismatch). **Static checked-in goldens + `go test -update ./internal/cli/...` regeneration** — identical discipline to the render package. Documented in `internal/cli/report_test.go`'s package comment so reviewers know how to update goldens.

The existing render-package tests stay untouched; they cover Cluster / Pair / Metric shape rendering individually. The new tests cover the *composition* layer: filtering, mode, size-cap, fail-quiet, marker, ordering.

### 2. Composite action (`.github/actions/audit-pr-comment/action.yml`)

Mirrors the structure of `publish-catalog-reusable.yml`: wraps `audit-core` plus the new render step.

**Inputs:**

| Name | Default | Purpose |
|---|---|---|
| `root` | `.` | Repo root to scan (forwarded to audit-core). |
| `audit-binary-version` | `v1` | Forwarded to audit-core; same resolution semantics (v1 / latest / v1.2.3 / build-from-source). |
| `languages` | `''` (auto) | Forwarded to audit-core. |
| `include-tests` | `false` | Forwarded to audit-core. |
| `include-file-hashes` | `true` | Forwarded to audit-core. |
| `marker` | `code-audit-pipeline-v1` | Sticky comment marker. Forwarded to both `code-audit report --marker` and `marocchino/sticky-pull-request-comment@v2 header:`. |
| `size-cap-bytes` | `60000` | Forwarded to `code-audit report --size-cap-bytes`. |
| `on-extraction-failure` | `quiet` | Forwarded to `code-audit report --on-extraction-failure`. |
| `github-token` | `${{ github.token }}` | Forwarded to audit-core and to the marocchino step. |

**Outputs:**

| Name | Purpose |
|---|---|
| `comment-path` | Path to the rendered `comment.md` (for downstream debugging / artifact upload). |
| `clusters-touched` | Integer count parsed from the touched-window-debt-summary metric. Lets consumers gate downstream jobs on "PR actually has structural impact". |

**Steps:**

1. **Checkout HEAD.** `actions/checkout@v6` with `ref: ${{ github.event.pull_request.head.sha }}`.
2. **Compute HEAD catalogs.** `uses: ./.github/actions/audit-core` (or `jakebromberg/code-audit-pipeline/.github/actions/audit-core@v1` when consumed externally) with `root`, `binary-version`, `audit-root: /tmp/audit-head`. Output: `head_catalogs_dir`.
3. **Resolve touched files.** Bash step calling `scripts/resolve-touched.sh`. The script:
   - Calls `gh pr view ${{ github.event.pull_request.number }} --json files --jq '.files[].path'` to get the raw touched-file list.
   - For each language the audit-core step detected, if the extractor has `--list-relevant` (TypeScript today), pipes the raw list through `code-audit extract <lang> --list-relevant` to apply the canonical walk predicate.
   - For languages without `--list-relevant` yet (Swift, Go, file-hashes), falls back to extension-glob matching against a per-language allowlist (mirrors what each extractor's walker uses today; documented as a deferred convergence to a flag-based shared predicate).
   - Concatenates the per-language results, deduplicates, normalizes path separators, and writes `/tmp/audit/touched.json` as a JSON array.
4. **Render.** `code-audit report --root /tmp/audit-head --touched /tmp/audit/touched.json --mode pr-comment --marker "${{ inputs.marker }}" --size-cap-bytes "${{ inputs.size-cap-bytes }}" --on-extraction-failure "${{ inputs.on-extraction-failure }}" --output /tmp/audit/comment.md`.
5. **Post sticky comment.** `marocchino/sticky-pull-request-comment@v2` with `header: ${{ inputs.marker }}` and `path: /tmp/audit/comment.md`.
6. **Emit outputs.** Read `clusters-touched` from `comment.md` (the metric header line) and set step output.

**No baseline cache in v1.** Earlier drafts of this plan proposed computing and caching the baseline catalog (keyed on `pull_request.base.sha`) even though the v1 filtering rule doesn't read it. The plan reviewer correctly pointed out this is dead I/O — and worse, it pins a cache-key design that v2 would either inherit or have to break. **The v1 composite does NOT touch `actions/cache`.** It computes HEAD catalogs only.

When baseline-diff filtering lands (a follow-up ticket extending the filtering rule to "new cluster member introduced by this PR" vs "pre-existing member touched"), that ticket will introduce the cache layer with full design freedom — and the cache-key correctness story (`base.sha` not `base.ref`) is documented in the setup doc now so the follow-up doesn't have to relitigate it. The acceptance checklist's cache-key items are deferred to the baseline-diff follow-up.

This is a deliberate scope contraction from the issue body, which prescribed cache-restore-then-recompute-on-miss for v1. The justification: the cache only earns its keep when it's actually read, and the v1 filtering rule is HEAD-only. Shipping the cache layer now risks calcifying a design before its consumer exists.

**Output emitter has no baseline-cache-hit field anymore** — see "Outputs" table below.

### 3. Reusable workflow (`.github/workflows/pr-comment-reusable.yml`)

Wraps the composite for orgs that prefer a central `uses:` workflow. Mirrors `publish-catalog-reusable.yml` shape:

```yaml
name: PR-comment audit (reusable)
on:
  workflow_call:
    inputs:
      audit-binary-version: { type: string, default: v1 }
      root: { type: string, default: '.' }
      languages: { type: string, default: '' }
      include-tests: { type: boolean, default: false }
      include-file-hashes: { type: boolean, default: true }
      marker: { type: string, default: code-audit-pipeline-v1 }
      size-cap-bytes: { type: number, default: 60000 }
      on-extraction-failure: { type: string, default: quiet }
      runner: { type: string, default: ubuntu-latest }
permissions:
  contents: read
  pull-requests: write
concurrency:
  group: code-audit-${{ github.event.pull_request.number }}
  cancel-in-progress: true
jobs:
  comment:
    if: github.event.pull_request.draft == false
    runs-on: ${{ inputs.runner }}
    steps:
      - uses: actions/checkout@v6
        with:
          ref: ${{ github.event.pull_request.head.sha }}
      - uses: jakebromberg/code-audit-pipeline/.github/actions/audit-pr-comment@v1
        with: { ... forward every input ... }
```

**Trigger guidance for consumers** (documented in the template + setup doc, not hardcoded in the reusable):

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
    paths-ignore: ['**/*.md', '.github/**', '.gitignore', 'LICENSE']
```

The `paths-ignore` is documented but NOT defaulted into the reusable — Markdown / workflow changes might legitimately touch source files the audit catalogs. Consumers opt in to the path filter explicitly.

### 5. Selftest workflow (`.github/workflows/pr-comment-selftest.yml`)

Runs the action against this repo as fixture. Triggered on `pull_request` and `workflow_dispatch`. Two jobs:

1. **dogfood-self**: invokes the local composite action against the current repo. Asserts that the resulting `comment.md` exists, is non-empty, and contains the sticky marker. Snapshots the body to an artifact for inspection.
2. **cache-correctness**: synthetic two-phase test simulating "main advances mid-PR" using `pipeline/_tests/test_pr_comment_cache_correctness.sh`. Runs the action once against a fixture base SHA, advances the fixture base, reruns, asserts the baseline cache was recomputed (`baseline-cache-hit: false`).

## Testing plan

### Renderer (Go) — fast, runs in `go test ./...`

- `internal/cli/report_test.go` — table-driven against `testdata/pr-comment/`:
  - **no-impact**: catalog with clusters, touched.json empty → "no structural impact" body.
  - **one-cluster**: catalog with one cluster whose members include a touched file → exactly one cluster section.
  - **multi-shape**: catalog with cluster + pair + metric → all three shapes render correctly.
  - **extraction-failed**: catalog file absent or unreadable → fail-quiet body, exit 0 (`--mode pr-comment --on-extraction-failure quiet`).
  - **size-capped**: catalog with 200+ clusters → output truncated at `--size-cap-bytes`, footer appended.
  - **marker-emission**: first line is `<!-- code-audit-pipeline-v1 -->` in pr-comment mode; absent in text mode.
  - **deterministic-ordering**: same input twice → byte-identical output. The test verifies the *composition layer* (filtering, marker, mode, section ordering) is deterministic; it does NOT verify per-query result ordering, which is jq's responsibility. Documented in `report_test.go`'s package comment: "callers requiring deterministic query result order must rely on jq's documented `-S` (sort-keys) flag or query-level ordering predicates."
  - **touched.json-normalization**: paths with `./`, CRLF, backslash separators all match catalog `.file` entries.
- Golden fixtures are checked in. Tests compare bytes, not parsed structure.

### Composite action — slower, runs in `act` or selftest workflow

- `.github/workflows/pr-comment-selftest.yml`:
  - Job 1: dogfood. Open a self-PR with a known cluster-triggering change (e.g. duplicate a type). Assert `comment.md` body contains the duplicate name.

- Concurrency test (deferred from CI to a manual `workflow_dispatch` workflow due to GitHub Actions billing for 5-burst scripts): documented in setup doc, runnable on demand.

**Cache-correctness regression test is dropped** from this scope (no cache in v1). It moves to the baseline-diff follow-up ticket where it will assert the key tracks `base.sha`, not `base.ref`.

## Open questions for review

These mirror the issue's open questions; I'm pre-committing to answers below to surface them for review feedback rather than punting:

1. **`marocchino/sticky-pull-request-comment` is MIT** — confirmed, listed in plan. No re-litigation needed.
2. **Fail-loud vs fail-quiet on extractor errors** — plan ships fail-quiet as default in `--mode pr-comment`; consumers can override per-input. Justification: comment surface stays current, errors visible in runner logs, no merge-gate (which is the failure that bites adopters most).

Time-capping per-query is a follow-up if the dogfood phase shows it bites.
4. **Comment size limit** — plan hard-caps at 60,000 bytes (4KB headroom under GitHub's 65,536 cap). Truncation is per-section, not per-cluster.
5. **Polyrepo `--shared`** — plan adopts MVP Option A (omit `--shared` entirely for polyrepo, defer cross-repo-aggregation to #118). Option B (remote-repo fetch) is a future iteration on top of #118's substrate.
6. **Renderer choice (Go vs Node)** — plan diverges from the issue body. Justified in "Renderer choice" §; this is the most consequential plan decision.

## Risks

- **Cross-language touched-file resolution is uneven.** TypeScript uses the canonical walker; Swift/Go/file-hashes fall back to extension globs. **Mitigation:** documented in setup doc + plan; the gap is bounded (TypeScript is the most-deployed extractor); cross-language `--list-relevant` is a small follow-up ticket.
- **`code-audit report --mode pr-comment` couples the renderer to GitHub-comment specifics** (sticky marker, 60KB cap). **Mitigation:** the marker and cap are flags, not constants. A different consumer (Slack bot, Linear comment) supplies different values.
- **`.audit/config.yml` adds a fifth resolution path** (after env vars, flags, marker autodetection, audit-core defaults). **Mitigation:** documented precedence chain in setup doc; selftest exercises a config-driven run vs an inputs-driven run vs a defaults-only run.
- **Selftest dogfood can be noisy** during the first few PRs while goldens settle. **Mitigation:** selftest writes the comment body to a workflow artifact even when the assertion fails; PR author can inspect and update goldens via a sibling PR before the test gates merges.
- **`internal/diffmatch/pathnormalize.go` introduces a second source of truth for path normalization** alongside `extractors/typescript/_lib/walk-predicate.mjs`. **Mitigation:** parity test in `pathnormalize_test.go` reads the TypeScript-side fixture inputs verbatim and asserts byte-equal outputs. A future refactor can collapse to a single source (e.g. by having the TypeScript side shell out to a Go normalizer, or by code-generating both from a shared spec), but that's premature; two short, well-tested implementations with parity coverage is the lower-risk MVP.
